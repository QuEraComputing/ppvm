Expand description

A type that applies a Clifford gate given by its Heisenberg rule.

apply1(q, rule) applies the gate whose rule is rule (it maps P to G† P G) at qubit q; apply2 does the same for two qubits. How depends on the type:

  • A container of Pauli operators reads each Pauli’s bits at q as (x, z), calls rule, writes the returned bits back, and multiplies the Pauli’s sign by (−1)^flip. With B = bool it visits its Paulis one at a time; with an integer B each bit position is a separate Pauli. A container without signs ignores the flip.
  • Other types may evaluate rule on fixed inputs instead, e.g. an inverse tableau evaluates it on the gate’s generators to find which rows to multiply.

A container of Pauli operators with B = bool must call rule exactly once in apply1 and apply2 if it applies the gate, and not at all if it skips it (e.g. on a lost site). Check for loss before calling rule. Wrappers such as Phased take the sign flip from that one call, so an extra or early call gives a wrong sign. Types that evaluate rule on fixed inputs are not bound by this and cannot be wrapped that way.

Implementing this trait gives Clifford through the blanket impl, so a type must not also implement Clifford by hand.

fn apply2( &mut self, a: usize, b: usize, rule: impl Fn([Self::B; 4]) -> ([Self::B; 4], Self::B), )

Apply a two-qubit rule at qubits a, b; the rule’s bits are [x_a, z_a, x_b, z_b]. For controlled gates a is the control.
