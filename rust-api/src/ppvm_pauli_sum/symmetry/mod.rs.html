4//! Lattice translation symmetry groups for operator-space Pauli evolution.
5//!
6//! A [`TranslationGroup`] represents a finite abelian group `G` acting on
7//! qubit positions by permutations. Given such a group, every Pauli word
8//! belongs to a translation orbit, and operator dynamics that commute
9//! with `G` can be tracked using **one canonical representative per
10//! orbit** instead of all `|G|` orbit members — reducing per-step memory
11//! and compute by a factor up to `|G|`.
12//!
13//! Following Teng, Chang, Rudolph, and Holmes (arXiv:2512.12094), this
14//! module implements **plain (real-coefficient) merging** of Pauli sums
15//! into orbit-representative form — see [`canonicalize_pauli_sum`] and
16//! [`symmetry_merge_pauli_sum`]. This handles observables in the trivial
17//! (`k=0`) symmetry sector, e.g. sums of single-Z operators over the
18//! lattice.
19//!
20//! **Non-trivial momentum sectors (`k ≠ 0`)** fold with the character
21//! phase `χ_k(g)` of each translation. Two conventions share one core:
22//! [`canonicalize_pauli_sum_complex`] *averages* over each orbit's
23//! distinct members (`1/|orbit|`), while
24//! [`momentum_merge_pauli_sum_pair`] *sums* — the convention that is
25//! idempotent on every orbit and reduces exactly to
26//! [`symmetry_merge_pauli_sum`] at `k = 0`. Note `|orbit| = |G|` only for
27//! free orbits, so the two are **not** related by a global `|G|` factor.
28//! On the Python side, an operator in sector `k` is carried as a *real
29//! pair* (real + imaginary components, two real `PauliSum`s) and merged
30//! via `PauliSum.momentum_merge` — letting gate-based Trotter evolution
31//! stay symmetry-compressed in any momentum sector with real
32//! coefficients throughout.
33//!
34//! ## Data model
35//!
36//! A `TranslationGroup` is specified by a list of generator permutations
37//! and their exact cyclic orders. [`TranslationGroup::order`] is the
38//! abstract product of those orders. The combined permutation action need
39//! not be faithful: different mixed-radix counters can induce the same
40//! permutation, so the action may have a kernel and
41//! [`TranslationGroup::orbit`] may repeat words. For instance, a 2D
42//! `L × L` torus has two generators (translation in x and y) each of
43//! order `L`.
44//!
45//! ## Canonicalization
46//!
47//! [`TranslationGroup::canonicalize`] returns the **lex-minimum** Pauli
48//! word reachable from the input via group action. The ordering is the
49//! standard `Ord` impl on `PauliWord` (compare `xbits`, then `zbits`).
50//! All orbit members canonicalize to the same representative; orbits are
51//! disjoint by construction, so the rep uniquely identifies the orbit.
52//!
53//! ## Merging
54//!
55//! [`canonicalize_pauli_sum`] takes parallel `Vec<Word>` / `Vec<f64>`
56//! buffers (the representation used by ppvm-lindblad's adaptive
57//! evolution) and replaces each Pauli by its canonical rep, summing
58//! coefficients for collisions. The output is an orbit-rep basis with
59//! coefficients equal to the sum of the input coefficients over each
60//! orbit's members. For dynamics that commute with `G` and initial
61//! states that are also `G`-invariant, this preserves the expectation
62//! value of any `G`-invariant observable (Theorem 1 of arXiv:2512.12094).
63//! This real-coefficient merge sums collisions. By contrast, complex
64//! projection into the trivial (`k=0`) momentum sector averages over the
65//! distinct members of each orbit. Non-trivial sectors incompatible with
66//! an orbit stabilizer project that orbit to zero.
67//!
68//! See the dedicated tests for correctness against full-basis evolution
69//! on small systems with no truncation.
